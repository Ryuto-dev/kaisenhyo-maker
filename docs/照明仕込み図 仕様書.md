# 照明仕込み図Webアプリ 仕様書

Oct 31, 2026 · @Ryuto

ライブハウスから大規模ホール、学園祭まで使える、ローカル保存を基本とした照明仕込み図の作図Webアプリ。面倒な作業は自動化して作図に集中でき、しかも何にも縛られない自由度を持たせる。

## 目的と前提

照明仕込み図を、配置の検討から印刷・共有までブラウザだけで完結させる。確定済みの前提は次の通り。

| 項目 | 確定内容 |
| --- | --- |
| 使用場面 | ライブハウス・小劇場、ホール・ツアー規模、学園祭などの学生イベント。用途は絞らない汎用ツール |
| 動作形態 | ブラウザ完結・ローカル保存を基本とし、後からクラウド同期を足せる構造にする |
| 出力 | PDF印刷（A3/A4）、SVG/PNG画像、灯体リスト・回路表（CSV/Excel） |
| 重視する点 | 使いやすさ・見やすさ、プロの現場に耐える品質、設計以外に頭を使わせないこと、縛られない自由度 |

DXFなど他CADとの連携、コンソール制御、3D表示は初期の対象外とし、将来候補として「開発範囲」に置く。

## 設計原則

使いやすさと自由度は衝突しやすい。そこで「標準は賢く、すべて上書きできる」を軸に、次の5原則で機能の採否を判断する。

1. **見やすさ優先**: 画面で見た図がそのまま印刷される。ラベルの重なりは自動で避け、印刷時の最小文字サイズは既定で6pt以上にする。
2. **設計に集中できる**: 用紙・枠・凡例・灯体表・採番・負荷計算・保存は自動で行う。ユーザーが決めるのは「どこに何を吊るか」だけにする。
3. **プロの現場に耐える**: 縮尺と寸法（mm）が正確で、版（Rev）を管理でき、オフラインでも動き、数百〜数千灯でも軽い。主要操作はキーボードだけで完結する。
4. **縛られない自由度**: 灯体・記号・属性・用紙・縮尺のプリセットは出発点にすぎず、すべて追加・変更・削除できる。吊り物に載せず自由に置くことも、規格外の機材を作ることもできる。
5. **データを囲い込まない**: 全データを1ファイルで書き出せる。他のツールへ移る自由を残す。

機能を足すかどうかは「作図の手数が減るか」「制約が減るか」で決め、どちらでもなければ入れない。

## 開発範囲

最初に「使える図が描けて印刷できる」状態をMVPとし、現場で頼れる機能をv1で足す。クラウド関連は将来に回す。

| 段階 | 含める機能 |
| --- | --- |
| MVP | 無限キャンバスと縮尺・用紙設定 / 標準灯体ライブラリの配置 / バトン・トラスなど吊り物の作図 / テキスト・図形・下敷き画像 / 灯体ごとの属性入力（ユニット番号・回路・DMX・色・用途） / 灯体リストのCSV出力 / PDF・PNG・SVG出力 / 自動保存とファイル書き出し / 元に戻す・やり直し |
| v1 | レイヤー / 自作灯体（SVG取り込み） / 自動凡例・タイトルブロック / 回路表・色表・DMXパッチ表 / 電源負荷の自動計算 / 側面図ビュー / 等間隔配置・配列複製 / テンプレート / Excel出力 / 版（Rev）管理 / タブレット操作の最適化 / 英語UI |
| 将来 | クラウド同期・共有リンク・共同編集 / DXFなど他CADとの連携 / コンソール向けパッチ情報の書き出し / 3D・ビジュアライザ連携 |

## 機能要件

機能は作図・灯体・吊り物・属性・自動化・表・下敷きの7群に分ける。（v1）と付けた項目以外はMVPに含める。

| 区分 | 要件 |
| --- | --- |
| 作図 | 無限キャンバス、ズーム・パン。グリッドとスナップは切り替えでき、間隔も変えられる。複数選択、回転、整列、等間隔配置、グループ化。位置と寸法はmmで数値入力できる。 |
| 灯体 | ライブラリから配置するか、名前で検索して配置する。種別はPAR、フレネル、スポット、ムービング、LEDバー・ウォッシュ、ブリンダー、ストロボなど。記号は汎用デザインとし、メーカー固有のロゴや意匠は使わない。向きとビームの方向を表示できる。 |
| 吊り物 | バトン、トラス、スタンド、床置きを描ける。灯体を載せると一緒に動く。載せずに単独で置くこともできる。 |
| 属性 | ユニット番号、チャンネル、回路（ディマー）、DMXユニバースとアドレス、色（ゲル番号または任意色）、ゴボ、用途（エリア・ターゲット）、消費電力（W）、高さ、メモ。項目は自由に追加できる。 |
| 自動化 | 並び順ルールを選べる自動採番（上手→下手、バトン順など）。属性の一括変更。同種灯体をN灯等間隔に一括配置（v1）。回路とDMXアドレスの重複を警告する。ラベルは重なりを自動で避ける。 |
| 表 | 灯体リスト（種別ごとの数量と消費電力合計）を自動生成する。回路表・色表・DMXパッチ表は（v1）。表と図は常に同期し、表側の編集が図に反映される。 |
| 下敷き | 会場図面の画像を取り込み、2点を指定して縮尺を合わせられる。 |

## 画面とUI

画面は「ライブラリ・キャンバス・プロパティ・灯体表」の4領域に絞り、デザインや設定に迷う場面を作らない。

- **画面構成**: 左に灯体ライブラリと検索、中央にキャンバス、右に選択物のプロパティ、下に開閉式の灯体表。最下行に縮尺・座標・選択数・保存状態を常時表示する。ツールバーは最小限にする。
- **キーボード第一**: すべての操作にショートカットを割り当てる。Cmd/Ctrl+Kのコマンドパレットで機能名を検索して実行でき、メニューを探す手間をなくす。
- **図と表の連動**: 表の行を選ぶと図上で灯体が強調され、図で灯体を選ぶと表の行が選択される。
- **見やすさ**: 用途・系統・種別での色分けを切り替えられる。ラベルの重なりは自動回避し、ズームに応じて表示するラベルの量を変える。印刷プレビューはカラーと白黒を切り替えられる。ダークモードにも対応する。
- **タッチ操作（v1）**: タブレットはピンチズームと2本指パンに対応する。スマホは閲覧を中心にする。
- **現場での安心感**: 保存状態を常に表示し、保存に失敗したときは目立つ警告を出す。元に戻す履歴は一覧から任意の時点へ戻せる。

## データモデルと保存

データは「プロジェクト → シート（図面1枚）→ レイヤー → オブジェクト」の階層で持つ。

| 対象 | 主な項目 |
| --- | --- |
| プロジェクト | 名称、会場、公演名、版（Rev）、作成者、単位、スキーマ版 |
| シート | 用紙サイズ、縮尺、向き、ビュー種別（平面・側面）、タイトルブロック設定 |
| レイヤー | 名称、表示・ロック、色 |
| 灯体 | ID、灯体種別への参照、x・y・z（mm）、回転、ユニット番号、チャンネル、回路、DMXユニバース・アドレス、色、ゴボ、用途、メモ、自由項目 |
| 灯体種別（ライブラリ） | 名称、記号（SVG）、消費電力、ビーム角、DMXチャンネル数、既定の属性 |
| 吊り物 | 種類（バトン・トラス・スタンド）、始点・終点、名称、載せている灯体 |
| 図形・テキスト・画像 | 位置、寸法、線と塗り。画像は縮尺合わせの情報を持つ |

保存は次の方針とする。

- 保存先は端末内。変更のたびにブラウザ内のデータベース（IndexedDB）へ自動保存し、ファイル（JSON、画像込みはzip）としても書き出し・読み込みできる。
- すべてのオブジェクトに固定のIDを持たせ、変更を「コマンド」として記録する。元に戻す・やり直しと、将来のクラウド同期を同じ仕組みで実現する。
- スキーマ版を持ち、古いファイルは読み込み時に新しい形式へ自動変換する。
- 端末内に直近の自動バックアップを複数世代残す（既定は20世代）。
- 自作の灯体ライブラリは単独ファイルで書き出して共有できる。

## 出力仕様

出力はすべて画面と同じ図面データから生成し、見たままの結果を保証する。

| 形式 | 内容 | 要件 |
| --- | --- | --- |
| PDF | A3/A4、縦横、複数ページ | ベクター出力。日本語フォントを埋め込み、文字化けさせない。縮尺・タイトルブロック・凡例を付ける。用紙に収まらない図はページ分割か縮尺の自動調整を選べる |
| PNG | 解像度を指定（最大300dpi相当） | 背景は白か透過を選べる |
| SVG | 他ソフトで編集できる形 | 文字はテキストのまま出力し、レイヤーごとにグループ化する |
| CSV | 灯体リスト（MVP）、回路表・色表・DMXパッチ表（v1） | UTF-8（BOM付き）でExcelでも文字化けしない。列と並び順を選べる |
| Excel（v1） | 上記の表を1ファイル・複数シートにまとめる | 見出し固定、列幅調整、印刷設定済み |

## 非機能要件

数値は目標値で、実装後に実機で検証して見直す。

- **性能**: 2,000オブジェクトの図面でパン・ズームが滑らか（目標60fps、最低30fps）。操作への反応は100ms以内を目安にする。
- **オフライン**: PWAとして、2回目以降は通信なしで起動・編集・保存・出力まで動く。
- **信頼性**: 自動保存と世代バックアップにより、タブを閉じても直前の状態に戻れる。
- **対応環境**: 最新のChrome・Edge・Safari（iPadのSafari含む）。ファイルへの直接上書き保存はChromium系のみで、他は書き出し・読み込みで代替する。
- **言語**: 日本語UIを標準とし、英語切り替えはv1で対応する。
- **プライバシー**: ローカルで完結する間は図面データを外部へ送らない。
- **運用**: 静的ファイルだけで配信でき、サーバーの運用を必要としない。

## 技術構成案

以下は推奨案で、実装前に変更できる。要点は、作図の中核（データ・描画・コマンド）をUIから独立させること。これにより、UIの作り直しやクラウド同期の追加が図面処理に影響しない。

| 領域 | 推奨 | 理由 |
| --- | --- | --- |
| 言語・ビルド | TypeScript + Vite | 型でデータモデルを守れる。静的配信に向く |
| 描画 | SVG（画面と出力で同じコード） | 見たまま出力でき、ベクターのPDF・SVGが作りやすい。1,000灯を超えて重くなればCanvas描画へ切り替える（図面データは共通） |
| 状態管理 | 単一のドキュメントストア + コマンド履歴 | 元に戻す・やり直しと将来の同期を同じ仕組みで扱える |
| 保存 | IndexedDB + File System Access API | 自動保存とファイル保存を両立する。使えない環境は書き出し・読み込みで代替 |
| PDF出力 | ブラウザの印刷（用紙サイズ指定）またはSVG→PDF変換ライブラリ | 日本語フォントの埋め込みを試作で確認して決める |
| Excel出力 | ExcelJSなど | ブラウザ内で完結する |
| 配信 | PWA（Service Worker）+ 静的ホスティング | オフラインで動き、サーバーが要らない |
| UI部品 | 任意（慣れているもの） | 作図の中核を分離しておけば後から変更できる |

- [ ] 側面図ビューをMVPに入れるか（v1に回す）
